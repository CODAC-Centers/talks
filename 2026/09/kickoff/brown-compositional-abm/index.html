Core Abstraction: Rewrite Rules

Rewrite rules come up frequently in theories of discrete updates of combinatorial data.
Definition (Rewrite rule)
A rewrite rule in a category \(\mathsf{C}\) is a pair of morphisms \(L \leftarrowtail K \rightarrow R\).
  • \(L\) is the pattern of the rule.
  • \(R\) is the replacement.
  • \(K\) relates the two.
A rewrite rule is applied to an object \(G \in \mathsf{C}\) via a pattern match \(L \to G\).
The result of applying the rule is determined by the structure of \(\mathsf{C}\) (namely, its pushouts).
[1] A. Aguinaldo. Topos Institute Blog, 2022 · image
3

Matt Klawonn already hinted at rewrite rules earlier in the day, so let me give more intuition for them. They're an important means of expressing discrete updates to combinatorial data.

(read slide)

I'll note that one reason these are particularly nice is that they blur the line between algorithm and data. Normally we're used to thinking of functions which can be applied to update data as something that lives in code. But a rewrite rule is finite, combinatorial data. So we can do operations on rewrite rules in a way that is very hard to do on code itself (this is underscoring James' earlier point which was that he doesn't want to ___ with models, he wants to ____ with algorithms.)

Agent-Based Modeling (1/3)

An agent-based model simulates individuals which interact with their environments.
To develop a model–implementation distinction, we need to be more precise. An ABM requires a schema to structure its individuals and their environment.
AlgebraicJulia implements a compositional theory of relational data.
  • Schemas are categories, database instances are functors \(\mathsf{C} \to \mathsf{Set}\).
  • Functors \(\mathsf{C}\to\mathsf{D}\) induce canonical migrations \([\mathsf{C},\mathsf{Set}]\to[\mathsf{D},\mathsf{Set}]\).
Caution: we do not impose a hard boundary between individual and environment.
5

So how will we move beyond this broad, hand-wavy definition? Let me share some work-in-progress with John Baez, Nathaniel Osgood, Xiaoyan Li, Evan Patterson, and Sean Wu on a more precise class of models.

Here's an example schema. An instance is a choice of a set of people, a set of vertices, a set of edges with source and target vertices, and so on. We have a category of instances, meaning we can talk about rewrite rules in this category.

For example, we might think of Person as tracking individuals, S I V as tracking properties of the individuals, and E and V as tracking the environment. However, if our notion of "action" is broad enough, we need not reify the distinction between individuals and environment. (You could argue that everything is being treated like an agent, the rows in the database, or that nothing is: it's just an environment.)

Agent-Based Modeling (2/3)

The semantics of models are continuous time with discrete events and continuous dynamics.
To first order, an ABM is:
  • A schema: possible world states are ACSet instances
  • A collection of rewrite rules \(\rho_i\)
    • An associated collection of timers \(T_i :: \mathsf{P}([0,\infty])\)
6
Now we need to introduce the possible actions. These are rewrite rules. If you just had a set of rewrite rules, you would have no control over which ones execute, how often, or in what order. This is where 'timers' are relevant.

Scheduling Future Events with Timers

A timer's probability measure is a residence time: how long the event takes to happen, conditional on nothing else happening first to remove it from that state.
Example: an SIR event schedule
7

The timer characterizes: how long (once the preconditions for an action hold) until the action happens? Note we can represent non-Markovian processes. This is because coarse-grained dynamics aren't memoryless.

This is a distribution we'll sample right when the match for a rewrite rule appears. This allows us to avoid needing instantaneous probabilities and integrating over small timesteps.

Here's an example. We start off with two infected, one susceptible people at the same location. So the possible events are that the two infected people recover or that they each infect the one susceptible person. If this were our initial state we'd draw from the distributions of these kinds of events to get scheduled times for all four events. Now it turns out that a recovery event occurs first, so when we evaluate that, the downstream infection event is invalidated. Then an infection event, then two recovery events.

Agent-Based Modeling (3/3)

These models are continuous time with discrete events and continuous dynamics.
To first order, an ABM is:
  • A schema: possible world states are ACSet instances
  • A collection of rewrite rules
    • An associated collection of timers \(T_i :: \mathsf{P}([0,\infty])\)
  • A collection of continuous dynamics, given by ODEs \(O_j\)
    • An associated collection of patterns \(P_j\)
    • Partial functions from \(P_j\) variables to \(O_j\) variables
8

I'll just comment that these discrete data structures and updates (though in continuous time) can also be gracefully integrated with continuous dynamics. In this example, we say "for every pair of infected people on the same vertex, the changes in their viral loads and antibody counts have the contributions of this ODE."

Just as certain discrete rules were presented by a Petri net, there are also graphical methods of presenting some classes of ODEs.

Rewrite-Based Workflows (1/4)

We're often interested in extended sequences of coordinated actions.
Problem: rules require matches, so the sequence above cannot specify how the rewrites relate to each other.
We address this by annotating the wires connecting boxes with interfaces.
To run the workflow, flow along wires with a distinguished match for whatever pattern lives on the wire.
9

Ok, so that was one proposal for what an "agent based model" is. It's quite expressive. Let me now talk about another approach to this problem, one that we could call 'rewrite-based workflows'. A naive approach to this looks like this sequence of rules. But because a rule needs a match to be applied, at most this says to apply the rules somewhere (anywhere), with no constraints on how the rule applications relate to each other.

We'll address this by annotating the wires. When you're stepping through a workflow, you are obligated to have a match of the shape of the pattern on the wire. Now it's possible to relate the output of rule 1 to the input of rule 2. Now, if R1 is not equal to L2, there must be some stuff in between. There are lots of primitive kinds of operations we can introduce to make this natural. But now I'm already talking about a graphical language with boxes and wires...

Rewrite-Based Workflows (2/4)

(Traced) symmetric monoidal categories are a desirable structure for one's syntax to have. Their diagrams:
Can be graphically depicted
Can have varying semantics
Can be composed in parallel or in series
Can be operadically substituted
We represent workflows in a category closely related to \(\mathsf{Meal}\):
  • Objects: sets. Morphisms: Mealy machines (stateful functions, updated when fed an input).
  • \(\mathsf{Meal}\) is a traced SMC.
[2] K. Brown and D. I. Spivak. arXiv:2304.14950, 2023

Applied category theorists know well the structure you need to interpret boxes and wires. I won't reiterate some of the virtues of this approach to syntax in the interest of time.

At the risk of making this too technical, I'll say something approximately true which is that we can interpret the boxes as Mealy machines (functions which have an internal state which gets updated by its input).

  • Nondeterministic Mealy machines
  • Each function has a multiset of outputs
Structured game representations
  • Probabilistic Mealy machines

Applications

The Incremental Search Problem (1/2)

Example (Incrementalizing a conjunctive query that looks for pairs of consecutive edges).
Suppose we have a binary \(\mathsf{edge}\) relation, and let \(\mathsf{edge'}\) be the relation after an update. Let \(\phi' = \mathsf{edge'}(x,y) \wedge \mathsf{edge'}(y,z)\) be the query over the updated relation.
\[ \begin{aligned} \phi' &= \mathsf{edge'}(x,y) \wedge \mathsf{edge'}(y,z) \\ &= (\mathsf{edge}(x,y) \vee \mathsf{\Delta edge}(x,y)) \wedge (\mathsf{edge}(y,z) \vee \mathsf{\Delta edge}(y,z)) \\ &= \phantom{{}\vee{}} {\color{IndianRed} (\phantom{\Delta}\mathsf{edge}(x,y) \wedge \phantom{\Delta}\mathsf{edge}(y,z))} \qquad \textcolor{gray}{\text{two old edges}} \\ &\phantom{{}={}} \vee {\color{RoyalBlue} (\phantom{\Delta}\mathsf{edge}(x,y) \wedge \mathsf{\Delta edge}(y,z))} \qquad \textcolor{gray}{\text{an old edge, then a new edge}} \\ &\phantom{{}={}} \vee {\color{RoyalBlue} (\mathsf{\Delta edge}(x,y) \wedge \phantom{\Delta}\mathsf{edge}(y,z))} \qquad \textcolor{gray}{\text{a new edge, then an old edge}} \\ &\phantom{{}={}} \vee {\color{RoyalBlue} (\mathsf{\Delta edge}(x,y) \wedge \mathsf{\Delta edge}(y,z))} \qquad \textcolor{gray}{\text{two new edges}} \\ &= {\color{IndianRed}\phi} \vee {\color{RoyalBlue}\Delta\phi} \end{aligned} \]
13
Often the engine of the algorithms we work on is querying relational data. In simulations, the data is changing frequently but in small bits due to local actions. Here I show a standard perspective on incrementalizing a query. You can think of it as factoring a query into two parts, one which looks at only the old data and one which can look at both old and new data. Once you have done this factorization, then when you get a runtime data update, you can simply ignore the part of the query corresponding to old data and get precisely the new results which come from the updated data.

  • Incrementalize conjunctive queries in any quasitopos with finite subobject lattices
Example in the category of simplicial complexes.
The algorithm is much more efficient when implemented natively in this category than when the data is embedded as a regular database and the algorithm run there.
14

Our abstract notion of a query is a morphism in some category C. We want to be able to compute our matches once and then apply rewrite rules without having to recompute all the possible matches each time.

A paper I've been working on over the past year with collaborators addresses this in a very general setting. This is not just 'descriptive ACT' but has genuine measurable speedups relative to the state of the art.

In this example, we are working with simplicial complexes. We can factor the query problem (matches from Q into the result) into a bunch of smaller queries, one of which only depends on the input G, the rest also depending on the Delta.
